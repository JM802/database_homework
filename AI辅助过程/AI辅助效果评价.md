# AI辅助效果评价

## 一 任务说明中的八个问题

### 1. 大模型在哪些数据库设计环节发挥了较大作用？

我觉得帮助最大的是需求分析和整理第一版表结构。AI 把管理员开班、学生选退课、教师录成绩的流程分开列出来，我就能顺着每个角色要做的事核对数据。比如一门课可以开几个班，把课程和教学班分开以后，每个班由谁教、有哪些学生选，就容易画清楚了。

### 2. 大模型生成的 E-R 模型是否合理？存在哪些问题？

主要的实体和联系是合理的。一个学生可以选多个教学班，一个班里也有很多学生，用选课记录把两边联系起来很合适。我改动比较大的是教室。初稿把教室记在教学班上，一个班如果中途换教室，就没法填第二间。后来我把教室放到每条排课记录里，每个时段都能填自己用的教室。

### 3. 大模型生成的函数依赖和规范化结论是否准确？

对排课宽表的范式判断是准确的。它用班号和时间编号一起标识一条排课，但只看班号就知道班容量，所以这张宽表不满足第二范式。初稿还列过把教室编号也放进键里的方案。我检查了这个键。一个班在同一时段只用一间教室，所以班号和时间编号已经足够，教室编号留作外键就行。

### 4. 大模型生成的 SQL 是否存在错误？如何验证？

存在一些错误。比如，按课程和学期汇总的 Q08 第一次在 MySQL 上报了 1052，原因是连接的几个结果中都有课程号。我在连接条件里写明各列属于哪张表，再拿春季的 C001 核对。样本里有 15 条选课记录，其中 2 条已退，查询返回 13 名有效学生，和原始记录对得上。

### 5. 大模型生成的 JDBC 代码是否能够正常编译和运行？

可以。我把 Java 17 设为目标版本，保留下来的初版代码编译通过了。连上 MySQL 后，我在管理员菜单里加了一门测试课，重新查列表能看到它，改名后再查也能看到新名字。倒是测试脚本原先只认 F 盘的 JDK，后来改成从 JAVA_HOME 或 PATH 找，换个目录也能用。

### 6. 大模型是否能够正确处理事务和异常？

可以。比如AI生成的的选课事务能正确回滚。AI认为，选课要先写选课记录，再把班级人数加一。我在测试时故意让第二步出错，回头查库，发现刚写的记录也撤销了，人数还是零。重复添加课程时，程序也能提示课程号重复，回到菜单后还可以继续操作，说明大模型能够正确处理事务和异常。

### 7. 哪些问题必须依靠学生自己的数据库知识解决？

比如设计排课表时，我得自己判断哪些规则能靠主键和外键保证。比如两个班同学期用同一间教室，一个排周一第 1 至 2 节，另一个排第 2 至 3 节。两条记录都能通过主外键检查，还得让程序比较星期和起止节次，才能发现两个班在第 2 节占了同一间教室。

### 8. 如果完全依赖大模型完成数据库设计和编程，可能造成什么后果？

如果全交给 AI，我可能会因为程序演示成功，就以为设计也没问题。比如初稿按本学期现有的最大班号往后发号，连续建几个班都很正常。可一旦删掉编号最大的班，下次建班就可能用回旧号。没亲自推过这个过程，我也很难解释为什么删班后还得保留发号记录。



## 二 有代表性的 AI 纠错记录

### 案例一 退课后重选与唯一约束冲突

| 环节 | 记录 |
| --- | --- |
| 发现问题 | AI 初稿考虑对学号和班号加唯一约束。我拿“选课、退课、再选同一个班”的流程检查，发现退课后的旧记录需要保留。 |
| 分析原因 | 两次选课的学号和班号相同。若按这两个字段限制唯一，旧记录会挡住重选时插入的新记录。 |
| 修改结果 | 用选课记录号标识每次选课。选课事务只按学生、学期和课程检查已有的有效记录。 |
| 验证修复 | T13 保留退课历史，重选后课表使用新的有效记录号。T11 核对同一学期已选同一门课时，另一个班仍会被拒绝。 |

### 案例二 Q08 课程学期统计报错

| 环节 | 记录 |
| --- | --- |
| 发现问题 | 首次在 MySQL 跑 AI 起草的 Q08 时，报列名歧义错误 1052，课程学期统计没有输出。 |
| 分析原因 | 课程表和两组统计结果都有课程号，原来的 `USING` 连接无法明确同名列的来源。 |
| 修改结果 | 改成带表别名的 `ON` 条件，按课程号、学年、学期对齐，仍分别汇总选退课和任课数据。 |
| 验证修复 | 重新执行 Q08，春季样本 C001 返回 15 条选课、2 条退课、13 名有效学生、3 条任课。对照基线样本，合授和改分历史没有造成重复计数。 |

### 案例三 学生记录缺少绩点和退课详情

| 环节 | 记录 |
| --- | --- |
| 发现问题 | 我用需求清单核对学生选课记录，发现 JDBC 初版只显示分数或“已退课”，查不到绩点、退课时间和类型。 |
| 分析原因 | 有效记录的显示只读取分数，退课分支也没拿退课时刻和所属学期的时间窗口作比较。 |
| 修改结果 | 已录成绩按规则计算绩点。退课时间按北京时间显示，再根据学期窗口判定常规退课或期中退课。 |
| 验证修复 | T22 核对 0 分显示 0.0 绩点，未录成绩显示“暂无绩点”。T24 核对 3 月 2 日 10:01 显示常规退课，5 月 3 日 10:00 显示期中退课。 |
