# 高校教学管理系统业务需求分析

## 1. 背景与范围

系统管理学生、教师、课程、教学班、选退课和成绩。管理员维护基础资料并查看所有教学班的成绩统计；学生选退课并查询本人记录；教师管理自己任教教学班的成绩。业务范围包括登录、基础信息管理、教学班查询、选退课、成绩录入查询及课程统计。操作审计、自动排课、招生、学费和考勤不纳入本项目。

一门课程可以在同一学期或不同学期开设多个教学班。同一课程在同一学期开设的各教学班每周总课时数相同，具体上课时段可以不同；不同时段可以使用同一教室、由同一教师任教，时段重叠时教室和教师均不得重复占用。教学班记录学期、班号、每周上课时段、教室和容量，并支持多位教师合授。教学班号在全校永久唯一，格式为“学年标识-学期序号-流水号”，例如“2024-2025-1-001”。

## 2. 用户角色与权限

| 角色 | 账号 | 操作 |
|---|---|---|
| 管理员 | admin | 登录后维护学生、教师、课程、教学班及任课安排；随时查询全部教学班的学生名单、容量、有效选课人数、剩余名额和成绩统计。 |
| 教师 | 字母 t 加六位数字，如 t123456 | 登录后只能选择自己任教的教学班，随时查看该班学生名单、容量、有效选课人数和剩余名额，录入和修改该班成绩，查询该班统计。 |
| 学生 | 字母 s 加六位数字，如 s123456 | 登录后查看及筛选教学班、选退课、查询本人选退课记录和成绩。 |

每次受限操作都要核对登录身份及角色。停用学生或教师时同时停用其登录账号。停用账号不能登录，已有业务记录及其状态继续保留。

### 密码管理

密码采用 Java 自带的 PBKDF2WithHmacSHA256 生成哈希，迭代 600000 次，每个账号使用独立的 16 字节盐；数据库保存盐和哈希，不保存明文密码。管理员账号 admin 的永久固定登录密码为 Q7!mV2#rK9@pL4$xN8%t，系统不提供修改或重置管理员密码的功能。初始化数据预先写入该密码对应的固定盐和固定哈希，登录时按相同算法校验，不在运行时重新生成管理员哈希。学生和教师由管理员设置初始密码，创建账号时各自生成随机盐和哈希；学生和教师登录后可以修改本人密码，忘记密码由管理员重置。所选算法及独立加盐方式参考 [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。

## 3. 功能需求

| 编号 | 功能 | 要求 |
|---|---|---|
| FR-01 | 基础信息管理 | 管理员新增、查询、修改学生、教师、课程和教学班；无任何业务关联的数据允许删除，已有业务关联的数据不得删除，停用须符合 BR-13。管理员创建学期时确定开学日期，创建后不可修改。创建教学班时确定容量、教室和任课教师，创建后这三项不可修改。教学班一旦产生选课记录，所属课程、学期和每周上课时段即冻结，退课后仍保持冻结。同一课程同一学期各教学班的每周总课时数必须相同，上课时段允许不同；时段重叠的教学班不得使用同一教室或安排同一教师。 |
| FR-02 | 教学班查询 | 教学班列表展示课程、学期、班号、上课时段、教室及所有任课教师姓名；输入其中任一教师姓名都能查到该教学班。学生仅在第 1 至 3 周的选课阶段看到容量、有效选课人数与剩余名额，并可使用“有无余量”筛选；其他时间学生不看到这三项信息，也不能使用该筛选。管理员可随时查看全部教学班的学生名单和名额信息；教师可随时查看自己任教教学班的学生名单、容量、有效选课人数与剩余名额。名单为当前有效选课学生。 |
| FR-03 | 选课 | 开学后第 1 至 3 周内选择教学班；同一学生在同一学期对同一课程只能保留一个有效教学班，其他学期的修读记录不阻止选课。所选教学班不得与本学期已有有效选课的上课时段重叠，且不得超过容量。成功后保存本次选课记录并减少一个余量，失败则不留下部分更新。 |
| FR-04 | 退课与重选 | 开学后第 1 至 3 周可退课；第 10 周周日至周三，每名学生每学期最多额外退一门课，且该窗口不能选课。两种退课都保留选退课历史并减少有效选课人数；常规阶段退课后剩余名额增加，期中退课后不再开放名额供学生选课。常规窗口内退课后可以重选同一班，形成新记录；已有成绩时禁止退课。 |
| FR-05 | 成绩管理 | 任课教师为自己教学班中有效选课的学生录入、查询成绩，并可在首次录入后 168 小时内修改（含恰好满 168 小时）。当前成绩更新与修改历史在同一事务中保存，历史记录旧分数、新分数、修改教师和时间。学生仅查本人，管理员查询所有教学班。成绩修改历史属于成绩业务记录。 |
| FR-06 | 课程统计 | 按单个教学班或同一课程在指定学期内的全部教学班统计选课记录数、退课记录数、任课安排数、当前有效选课学生人数、平均分、平均绩点、及格人数与满绩人数（分数不低于 90）。各学期分别统计。 |
| FR-07 | 关联查询与异常反馈 | 提供涉及至少三张表的业务查询；对无权限、无记录、重复选课、无余量、超期、分数越界和数据库失败给出明确提示。 |

## 4. 核心业务流程

1. 管理员建立学期、课程和教学班，创建教学班时确定正整数容量，指定每周上课时段、教室及任课教师。重复班号、同一学期上课时段重叠且教师或教室相同、同一课程同一学期各教学班每周总课时数不一致时，系统拒绝保存；不同时段允许使用相同教师或教室。学期创建后开学日期不可修改。教学班创建后容量、教室和任课教师不可修改，有过选课记录后也不得修改所属课程、学期和每周上课时段。
2. 学生在选课阶段按教师姓名或余量筛选教学班并提交选课。系统依次检查登录身份、时间窗口、学生及课程和教学班的启用状态、同学期同课重复、学生时间冲突及余量；任一条件不满足即拒绝。通过后在一个事务中新增选课记录并更新有效人数。单用户顺序操作是本项目的运行范围，不支持并发选课。
3. 学生提交退课。系统核查有效选课、退课窗口、期中名额及成绩状态；通过后在一个事务中标记退课并减少有效人数。常规阶段退课增加剩余名额，期中退课不再提供选课名额。重复退课、超期退课及已有成绩均拒绝。
4. 教师随时查看自己任教教学班的当前有效选课学生名单及名额信息，为名单中的学生录入或修改成绩。系统检查权限、分数范围和修改期限，在同一事务中更新当前成绩并写入修改历史，任一步失败时全部回滚。学生查看本人分数及绩点。
5. 管理员查看单个教学班或指定学期的课程统计，教师查看任教教学班的统计。未录成绩时平均分和平均绩点均显示“暂无成绩”，及格人数和满绩人数为零。

## 5. 主要数据及关系

| 数据对象 | 业务信息与关系 |
|---|---|
| 账号 | 账号名、角色、密码哈希及参数、启用状态；学生和教师账号分别对应本人。 |
| 学生、教师 | 各自的唯一标识及基本资料。 |
| 课程 | 课程标识与基本资料；可在多个教学班开设。 |
| 学期 | 学年标识、学期序号、开学日期和结束日期；开学日期为周日且创建后不可修改，该周日为第 1 周首日，每周从周日开始，以此确定第 1、3、10 周。 |
| 教学班 | 全校永久唯一的班号、所属课程与学期、每周上课时段及课时数、教室、创建时由管理员确定且创建后不可调整的容量、有效选课人数和状态。全学期每周重复固定节次，各时段互不重叠并共用一个教室；同一课程同一学期各班的每周总课时数相同，具体时段可不同。剩余名额按容量减当前有效选课人数计算，管理员及本班任课教师随时可查。 |
| 任课安排 | 教学班与教师的对应关系，支持多位教师合授，每位任课教师均占用本班的全部上课时段。 |
| 选退课记录 | 学生、教学班、选课时间、状态、退课时间和退课类型；退课后仍保留历史。 |
| 成绩 | 对应一次有效选课，记录首次录入时间和当前分数。绩点根据当前分数按 BR-09 换算，不单独存储。成绩历史记录每次修改的旧分数、新分数、修改教师和修改时间。 |

学生与教学班通过选退课记录构成多对多关系；教师与教学班通过任课安排构成多对多关系。课程要求至少五个核心实体或数据表、一个多对多联系和一个涉及三张以上表的业务操作或查询，以上业务范围能够支撑这些要求。

## 6. 业务规则清单

来源分为课程要求、用户确定和根据上述业务推导的项目规则。以下规则均作为本项目的验收依据。

| 编号 | 规则 | 来源 | 验收依据 |
|---|---|---|---|
| BR-01 | 覆盖学生和教师管理、课程管理、选课退课、成绩录入查询及课程统计。 | 课程要求 | 逐项检查功能。 |
| BR-02 | 登录账号决定角色权限；管理员为 admin，教师和学生账号分别为 t、s 加六位数字。 | 用户确定 | 用三类账号验证允许与拒绝的操作。 |
| BR-03 | 密码用 PBKDF2WithHmacSHA256 迭代 600000 次后存储。admin 使用永久固定密码 Q7!mV2#rK9@pL4$xN8%t，并在初始化数据中保存预先计算的固定盐与固定哈希；管理员密码不能修改或重置。学生和教师账号分别使用独立随机盐，可修改本人密码或由管理员重置。数据库不保存明文密码。 | 用户确定 | 检查初始化数据无明文、管理员哈希跨次初始化一致，并验证三类账号的登录及密码修改权限。 |
| BR-04 | 教学班包含学期、永久唯一的班号、每周上课时段、教室和正整数容量。一门课程可开多个班，一个班可由多位教师合授；同一课程同一学期各班的每周总课时数必须相同，具体上课时段可以不同。全学期每周重复固定节次，不处理单双周、分段周次和临时调课。同一教学班的所有时段共用一个教室，每位任课教师均占用本班全部时段。同一学期、同一星期几的节次重叠时，不得复用教师或教室。教学班创建后容量、教室及任课教师不可修改。有任何选课记录后，所属课程、学期和每周上课时段不可修改。 | 用户确定；冲突判定为项目规则 | 创建同课时数但时段不同的多班样例，验证时段不重叠时复用教师和教室；尝试课时数不一致、重复班号、时段重叠且复用教师或教室、创建后修改容量、教室或任课教师，以及选课或退课后修改所属课程、学期或上课时段。 |
| BR-05 | 剩余名额等于容量减当前有效选课人数，不能小于零；成功选课使有效人数加一，成功退课使其减一。常规阶段退课后剩余名额增加；第 10 周退课后仍减少有效人数，但不能再选课。管理员及本班任课教师随时可查看当前有效选课学生名单、容量、有效选课人数和剩余名额；学生仅在第 1 至 3 周的选课阶段可查看三项名额信息并使用“有无余量”筛选，阶段结束后隐藏。 | 用户确定 | 验证管理员、教师和学生在选课阶段内外的名单和名额可见性、选课、两种退课及满额边界。 |
| BR-06 | 同一学生对同一教学班至多一条有效选课；退课保留历史，允许重新选并生成新记录。 | 用户确定 | 验证重复选课被拒、退课后重选成功。 |
| BR-07 | 学期开学日期在创建学期时确定，之后不可修改。开学日期为周日，从该日 00:00 起算第 1 周；每周为周日 00:00 至同一教学周的周六 23:59:59。常规选退课至第 3 周周六 23:59:59 截止。第 10 周周日 00:00 至周三 23:59:59，每名学生每学期最多额外退一门课，该窗口不能选课。所有时间按北京时间计算。 | 用户确定；秒级边界为项目规则 | 验证周日开学、创建后拒绝修改开学日期、各周起止、常规和期中窗口边界、期中第二次退课及期中选课被拒。 |
| BR-08 | 仅对有效选课录入成绩；已录成绩不得退课。任一当前任课教师可在首次录入成绩后不超过 168 小时修改，恰好满 168 小时仍允许修改，超过即拒绝。修改历史保留旧分数、新分数、教师和时间。 | 用户确定；起算点和历史字段为项目规则 | 验证跨班教师修改、恰好满 168 小时修改、超过 168 小时修改和成绩录入后退课被拒，并检查成绩历史。 |
| BR-09 | 成绩为 0 至 100 的整数，缺考录入 0 分。未录入显示“暂无成绩”。已录入的 0 分作为有效成绩参与统计。绩点按当前分数换算，不单独存储。低于 60 不及格、绩点为 0；60 至不足 70 对应 1.0，70 至不足 80 对应 2.0，80 至不足 90 对应 3.0，90 至 100 对应 4.0。所有合授教师均可修改自己任教班级的成绩。 | 用户确定，分数边界按不重叠区间整理 | 检查缺考、未录入、0、1、59、60、69、70、79、80、89、90、100 及越界值；用合授教师账号验证权限。 |
| BR-10 | 管理员可按单个教学班或指定课程和学期查看统计，教师只可查看任教教学班。课程统计仅汇总该课程在指定学期的教学班，不跨学期汇总。选课记录数、退课记录数和任课安排数按对应记录计数，重选产生的新选课记录另计。当前有效选课学生人数按统计范围内的有效选课记录按学生去重。平均分和平均绩点仅统计有效选课且已录入成绩的学生。平均分对当前分数求算术平均，平均绩点对各条当前分数按 BR-09 换算出的绩点求算术平均。及格人数统计其中达到 60 分的学生，满绩人数统计其中达到 90 分的学生。无已录成绩时，两项平均值显示“暂无成绩”，及格人数和满绩人数均为零。 | 用户确定；去重范围为项目规则 | 用同一学生跨学期修读同一课程并分别得 55 分、85 分的样例，核对两学期各自的平均分和及格人数。另验证同学期多班汇总、重选、缺考 0 分和未录成绩。 |
| BR-11 | 选退课记录和有效选课人数在同一事务中变更，任一步失败全部回滚。有效选课人数始终等于当前有效选课记录数。成绩修改在同一事务中更新当前成绩并写入修改历史，任一步失败全部回滚。 | 课程事务要求及用户确定 | 模拟两类事务途中失败，分别检查选退课记录与余量、当前成绩与修改历史是否恢复原状。 |
| BR-12 | 同一学生在同一学期对同一课程只能保留一个有效教学班；其他学期的选课记录不影响本学期选课。在同一学期，若每周固定节次与已有有效选课重叠，则拒绝选课。 | 用户确定；时间判定为项目规则 | 验证同学期选同课另一班或选重叠节次被拒，其他学期重修可在符合选课条件时成功。 |
| BR-13 | 已有业务关联的学生、教师、课程和教学班不得物理删除。教学班有过选课记录时不得停用，该课程名下任一教学班有过选课记录时，该课程也不得停用。已退课的历史记录仍适用此规则。其他对象按基础信息管理规则停用，历史记录及关联继续保留。停用学生或教师时同步停用其账号。 | 用户确定 | 验证管理员无法停用已有选课记录的教学班及其课程，包括所有学生已退课的情况。验证账号停用后不能登录，历史数据仍可查询。 |

## 7. 需求来源

课程明确要求的业务范围与功能列于 BR-01，事务要求体现于 BR-11；其余规则由用户补充或根据业务推导。为使规则能执行，新增选课要求学生、课程及教学班均已启用。退课检查已有的有效选课记录及退课条件，成绩只能对应有效选课，停用账号不能登录，任课教师只能选择自己的教学班，余量不能为负。这些约束均纳入后续数据库设计和程序验收。
