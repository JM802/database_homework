# 修改过程 1

本记录逐项回应[修改建议 1](../修改建议/修改建议1.md)。修改内容见[高校教学管理系统业务需求分析](../../需求分析文档/高校教学管理系统_业务需求分析.md)。

## 已修改

| 建议 | 修改结果 | 对应位置 |
|---|---|---|
| 1. 限定同课重复选课范围 | 同一学生在同一学期对同一课程只能保留一个有效教学班。往期修读记录不影响本学期选课。 | FR-03、BR-12 |
| 2. 明确统计范围 | 统计以单个教学班或“课程＋学期”为单位，课程统计仅汇总指定学期内该课程的教学班。将“最终人数”改为“当前有效选课学生人数”。例如，同一学生两个学期分别得 55 分和 85 分，若各学期都只有这一条成绩，则两个学期的平均分分别是 55 和 85，及格人数分别是 0 和 1。 | FR-06、核心业务流程第 5 步、BR-10 |
| 3. 限制停用 | 教学班有过选课记录就不能停用，课程名下任何教学班有过选课记录，该课程也不能停用。即使学生全部退课，历史选课仍触发此限制。有效选课继续计入人数，学生按原窗口退课，教师按原权限录入成绩。学生或教师停用时同步停用其账号，保留已有业务记录。 | 第 2 节、FR-01、FR-03、BR-13、第 7 节 |
| 4. 限制修改教学班和学期 | 教学班创建后固定容量、教室和任课教师。有过选课记录后，所属课程、学期和每周上课时段也固定，退课不会解除冻结。学期创建后固定开学日期。 | FR-01、核心业务流程第 1 步、BR-04、BR-07 |
| 5. 简化排课模型 | 全学期每周重复固定节次。一班使用一个教室，所有任课教师占用本班全部节次。时段重叠时不能复用教师或教室。单双周、分段周次和临时调课不纳入项目。 | 第 5 节、BR-04 |
| 8. 保障记录一致性 | 当前成绩更新和修改历史写入放在同一事务中，任一步失败都回滚。同时明确有效选课人数始终等于当前有效选课记录数。 | FR-05、核心业务流程第 4 步、BR-11 |
| 成绩与缺考 | 合法成绩为 0 至 100 的整数。缺考录入 0 分，绩点为 0，计入平均值。未录成绩显示“暂无成绩”，不计入平均值。 | BR-09、BR-10 |
| 成绩修改期限 | 从首次录入起算，恰好满 168 小时仍允许修改，超过 168 小时拒绝。 | FR-05、BR-08 |
| 密码管理 | 管理员使用永久固定密码，系统不提供修改和重置功能。学生和教师可修改本人密码，也可由管理员重置。PBKDF2WithHmacSHA256 使用 600000 次迭代。 | 第 2 节、BR-03 |
| 绩点换算 | 保存当前分数，按 BR-09 换算绩点。平均绩点对统计范围内已录入的有效成绩逐条换算后求算术平均。成绩记录不单独存储绩点。 | 第 5 节、BR-09、BR-10 |
