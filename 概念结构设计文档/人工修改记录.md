## 2. 任务一已有人工决定的落实

| 已有人工决定 | 任务二中的处理 | 关联需求 |
|---|---|---|
| 同课同学期各班每周总课时相同，具体时段可以不同；不重叠时可复用教师和教室。 | 早期将周上课时段设为依赖教学班的对象，本轮已改为教学班通过排课关联共享的上课时间。课时和冲突继续按班校验。 | FR-01、BR-04 |
| 一个教学班使用一个教室，每位合授教师占用本班全部时段；不处理单双周和临时调课。 | 早期将教室作为教学班属性，本轮已将教室独立建模。合授通过任课安排表达。 | BR-04 |
| 创建后容量、教室和任课教师固定；产生过选课记录后课程、学期和时段冻结。 | 保留这些属性和联系，按业务状态限制修改；退课历史继续触发冻结。 | FR-01、BR-04 |
| 开学日期为周日且创建后不可修改。 | 学期保存开学日期，据此派生教学周和操作窗口，不保存会随时间失真的当前周次。 | BR-07 |
| 学生同课只保留一个有效班的限制以学期为范围；退课保留历史，常规窗口内可重选。 | 通过教学班找到课程和学期；选课事件使用独立记录号，不把学生与班号组合设为全部历史的唯一键。 | FR-03、FR-04、BR-06、BR-12 |
| 已录成绩不能退课，成绩修改和历史保存必须同事务完成。 | 成绩依赖一次选课，修改历史独立保存旧分数、新分数、修改教师和时间。 | FR-05、BR-08、BR-11 |
| 分数为 0 至 100，缺考录入 0 分；恰好满 168 小时仍可修改。 | 无成绩对象表示未录入，0 分按有效成绩处理；首次录入时间保留以计算修改期限。 | BR-08、BR-09 |
| 绩点按分数换算，不单独保存。 | 成绩只保存当前分数，个人绩点、平均绩点及其他统计由既定规则计算。 | BR-09、BR-10 |
| 统计按教学班或课程加学期展开，选退课记录数与有效学生人数采用不同口径。 | 保留课程、学期、教学班、选课事件和任课安排各自的身份与联系，支持按范围计数与去重。 | FR-06、BR-10 |
| 学生只能在选课阶段看到名额信息，管理员及任课教师随时可按权限查看。 | 通过账号、角色、任课安排和选课记录确定可见范围；可见性作为业务约束保留。 | FR-02、BR-05 |
| 有业务关联不物理删除；有过选课的班及所属课程不可停用；人员停用时同步停用账号。 | 保留启用状态、身份绑定及历史联系，删除与停用保护独立说明。 | BR-13 |
| 密码使用 PBKDF2WithHmacSHA256，迭代 600000 次，管理员密码固定，学生和教师分别独立加盐。 | 账号保存盐、哈希及算法参数，不新增明文密码、失败锁定或首次登录强制改密属性。 | BR-02、BR-03 |

## 3. 两个已有 AI 问题的设计修正

| 已有问题及来源 | 原因与影响 | 任务二的修正 | 核对方式及边界 |
|---|---|---|---|
| AI 曾把“同课各班每周总课时相同”写成“具体时段相同”，见任务一人工修改记录第 2 节。 | 将课时量与时段安排混同，若把时段归到课程加学期，会强迫各班使用同一时段。 | 时段属于具体教学班，周课时由本班时段合计，同课同学期只比较课时总量。 | 自拟概念样例：A 班周一第 1 至 2 节，B 班周二第 3 至 4 节，均为每周 2 节。仅核对表达能力，尚非数据库测试。 |
| AI 初稿的主要数据同时保存当前分数和绩点，见任务一 AI 生成结果及人工修改记录第 4 节。 | 绩点由分数确定，重复保存会产生忘记同步更新的风险。 | 当前成绩保存分数，绩点派生；历史旧分数、新分数表示历史事实，继续保留。 | 自拟概念样例：85 分改为 90 分后，绩点由 3.0 派生为 4.0，历史保存 85→90。尚未实际执行 SQL 或事务。 |

以上属于任务一已留有来源的纠错及其在任务二的落实，不是本次整理中新发现的人工意见。

## 4. 原任务二 AI 复核与设计补充

下列内容来自原任务二的[AI 交互记录](../02_数据库概念设计/04_AI生成结果与交互记录.md)和[设计复核说明](../02_数据库概念设计/05_设计复核与人工修改说明.md)，属于 AI 辅助设计及复核，仍须由小组理解和确认。

| 复核事项 | 处理结果 | 依据或状态 |
|---|---|---|
| 任务一只概括要求基本资料，未逐项列出学生、教师和课程字段。 | 采用学号或工号、姓名、课程号或课程名及相应启用状态等最少资料，不扩展院系、专业等实体。 | 最少属性是本阶段的设计补充。 |
| 登录账号与学号、工号含义不同；两条可选一对一连线不能表达身份互斥。 | 将账号与人员标识分开，补充角色匹配及学生、教师绑定互斥，管理员不绑定两类人员。 | 一对一绑定及互斥仍须后续约束或业务校验保障。 |
| 学期、周时段和任课安排需要完整业务范围才能唯一识别。 | 分别使用“学年＋序号”“教学班＋星期＋开始节次”“教学班＋教师”联合标识。 | 周时段结束节次可替代开始节次；候选标识依赖同班时段不重叠。 |
| 退课后重选会重复出现同一学生与同一教学班。 | 每次选课使用独立记录号；成绩以所属选课记录号识别，修改历史另设独立编号。 | 支持选退历史、未录成绩和多次成绩修改。 |
| 有效人数既可由记录计数，又承担既定事务要求。 | 保留受控缓存；余量、绩点、周课时和统计值派生。 | 有效人数须等于有效选课记录数，选退课时同事务维护。 |
| 正容量、合法分数和引用联系不足以涵盖全部业务规则。 | 另列同课有效选课、排课冲突、窗口、权限、冻结、删除停用和事务一致性规则。 | 任务三、四再确定数据库约束与应用校验的具体分工。 |
| 初步设计要求班号前缀始终匹配当前所属学期。 | 改为创建时按当时学期生成，之后以所属学期联系判断当前归属；无选课时修改学期暂按保留原号解释。 | FR-01 允许选课前修改学期但未明确是否改号；保留原号是待小组确认的约定，不是已确定需求。 |
| 只检查现存班号不重复，不能证明班号永久唯一。 | 后续发号机制须防止已删除的无关联教学班旧号重新发放。 | 可考虑已发号登记或高水位机制，尚未实际实现和测试。 |

班号问题是原任务二材料已记载的 AI 初稿与复核修订。本次只保留其来源和状态，不将其写成小组成员已经认可的决定。
