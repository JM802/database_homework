# 任务三修改建议 1

**任务三的六项交付已齐。** 14 张关系表均有字段、主外键和逐表 1NF 至 3NF 分析，几个宽表例子也给出了分解过程。主要需要补清排课约束在分解前后的表达，以及逻辑字段的取值范围如何落到 JDBC。依据[任务书的任务三要求](<../../../大模型辅助数据库设计与JDBC编程_课程大作业(2).docx>)和[关系模式清单](../../关系模式清单.md)。

## 建议优先修改

1. **补充排课宽表中的教室占用依赖。** 在合法的排课宽表 `ScheduleWide` 中，同一学年、同一学期、同一时间编号和同一教室只能对应一个班，所以有 `(Y,N,T,R) → B`。结合已有依赖，这四个属性可以确定整行。分解后，`teaching_class` 保存学年、学期，`class_schedule` 保存时间与教室。两个子表各自的键可以同时合法，却仍允许同学期两个班引用同一时间、同一教室。建议补上这个反例，说明原有无损连接结论仍成立，依赖保持结论适用于已列出的结构性依赖，这条业务依赖需要跨表检查。验收时同时核对两个时间编号不同但节次重叠的例子。[关系分解第 2 节](../../关系分解.md) [任务一 BR-04](../../../需求分析文档/高校教学管理系统_业务需求分析.md)

2. **在数据字典中写清班内排课和修改限制。** 第 4 节已有教师、教室、学生冲突规则。再明确同一班的多条时段自身也不得重叠，即使教室不同。写明调整排课时改的是该班的排课记录，共享时间定义照常由其他班引用。有过选课记录后，所属课程、时段和教室继续冻结，退课后也一样。复核可用同一班周一第 1–2 节、第 2–3 节分别安排不同教室的例子，两段都包含第 2 节，应拒绝。[关系模式清单第 4 节](../../关系模式清单.md) [任务一 FR-01、BR-04](../../../需求分析文档/高校教学管理系统_业务需求分析.md) [任务二实体与联系](../../../概念结构设计文档/高校教学管理系统_数据库概念结构设计.md)

3. **统一教学班容量的可用上限。** T06 和 MySQL DDL 允许无符号 32 位容量，最大为 4,294,967,295。JDBC 创建教学班用 `Integer.parseInt`，多处查询用 `getInt`，2,147,483,648 已超出这些入口的表示范围。建议先确定项目使用的上限。若按 Java `int` 统一，可在逻辑数据字典、SQL 约束和应用输入中使用同一上限；若保留当前数据库范围，要同步扩宽 JDBC 的写入、读取和余量计算。用上限与上限加 1 各验证一次，覆盖建班及名额显示。[关系模式清单 T06](../../关系模式清单.md) [01_create.sql](../../../CourseSelectionSystem/sql/01_create.sql) [Main.java](../../../CourseSelectionSystem/src/main/java/edu/coursework/Main.java) [QueryService.java](../../../CourseSelectionSystem/src/main/java/edu/coursework/service/QueryService.java)

4. **确认学期日期互斥是否纳入逻辑模型。** JDBC 建学期与 SQL 审计检查不同学年的学期日期也不得重叠。任务一 BR-07 列出了同学年春季、小学期的衔接及各学期时长。若小组确认全库学期互斥是正式业务规则，补入关系模式清单，并在函数依赖分析中说明合法数据的 `start_date` 也可决定 `(academic_year, term_no)`。将语义候选键与当前数据库实际声明的主键区分开，日期唯一性本身只检查开学日重复。验收时用起始日期不同但区间重叠的两个学期检验。[关系模式清单第 4 节](../../关系模式清单.md) [函数依赖分析](../../函数依赖分析.md) [任务一 BR-07](../../../需求分析文档/高校教学管理系统_业务需求分析.md) [AdminService.java](../../../CourseSelectionSystem/src/main/java/edu/coursework/service/AdminService.java) [04_audit.sql](../../../CourseSelectionSystem/sql/04_audit.sql)
