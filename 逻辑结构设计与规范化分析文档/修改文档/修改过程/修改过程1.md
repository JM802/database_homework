# 任务三修改过程 1

本记录对应[修改建议 1](../修改建议/修改建议1.md)，记录本轮实际修改、未修改项及验证情况。

## 已修改

| 事项 | 修改过程与结果 | 位置 |
|---|---|---|
| 教室占用依赖 | 在 `ScheduleWide` 中补充业务依赖 `(Y,N,T,R) → B`，用同一学期、同一时间编号和同一教室被两个教学班使用的例子，说明分表后的主外键不能单独阻止占用冲突。原无损连接证明仍按原结构性依赖成立；新增业务约束须跨表校验。 | [关系分解第 2 节](../../关系分解.md) |
| 不同时间编号的重叠 | 补充不同时间编号也可能包含重叠节次，不能只比较编号。 | [关系分解第 2 节](../../关系分解.md) |
| 班内排课与历史冻结 | 明确同一班的时段自身不能重叠，调整时不修改其他班共用的时间定义；有过选课记录后课程、时间和教室继续冻结，退课不解除冻结。 | [关系模式清单第 4 节](../../关系模式清单.md) |

## 未修改的问题与原因

| 事项 | 当前状态和原因 |
|---|---|
| 容量范围在 MySQL 与 Java 之间不一致 | 尚未统一。数据库 `INT UNSIGNED` 的上限高于当前 Java `int` 的范围；本轮未确定统一上限，也未改表或缩窄已有数据。 |
| 不同学年的学期是否一律互斥 | 尚未作为新增业务规则写入逻辑模型，也未据此新增 `start_date` 候选键；程序及审计已有跨学年重叠检查，规则是否正式纳入模型仍需明确。 |
| 具体复核人和人工审查过程 | 本轮没有虚构人员身份或未实际发生的人工复核；由实际复核者补记。 |

## 验证

本轮以现有需求、关系分解和程序约束为依据进行文档核对；用户反馈 JDBC 和任务四两种样本的隔离测试均通过。
