# 高校教学管理系统关系模式清单

依据[任务一业务需求分析](../需求分析文档/高校教学管理系统_业务需求分析.md)与[任务二数据库概念结构设计](../概念结构设计文档/高校教学管理系统_数据库概念结构设计.md)。表结构按本机已有的 MySQL 8.0 设计，使用 InnoDB 和 utf8mb4。数据类型使用 [MySQL 8.0 数据类型参考](https://dev.mysql.com/doc/refman/8.0/en/data-types.html)中的名称。

## 1. 从 E-R 模型转换为关系模型

独立实体各建一表。1:N 联系的外键放在 N 端，1:1 联系通过非空唯一外键落实。多对多的任课和排课使用关联表。选退课是具有自身编号和时间的业务事件，同一学生退课后可再次选同一班。成绩的主键同时引用一次选课，同一次选课允许暂时没有成绩。成绩修改作为独立历史对象。任务二的 13 个业务对象各对应一个关系，另设班号发放计数关系，以免删除班后重用号码。

| 联系 | 转换结果 |
|---|---|
| R01、R02 账号与学生、教师 | 学生表和教师表各用非空唯一的账号名引用账号。应用同事务保证角色匹配、绑定互斥和人员账号成对创建 |
| R03、R04 教学班与课程、学期 | 教学班引用课程号和同一学年的学期键，班号前缀必须与学期相符 |
| R05、R13、R14 教学班排课 | 班号和时间编号组成联合主键，各自外键，教室编号为第三个外键 |
| R06、R07 任课安排 | 班号和工号组成联合主键，各自外键 |
| R08、R09 选退课 | 每次选课以记录号识别，分别引用学生和教学班 |
| R10 选课与成绩 | 成绩主键为选课记录号，同时是外键 |
| R11、R12 成绩修改 | 修改历史分别引用当前成绩和实际修改教师 |

## 2. 关系模式一览

```text
account(account_name, role_code, password_hash)
student(student_no, student_name, account_name)
teacher(teacher_no, teacher_name, account_name)
course(course_no, course_name)
academic_term(academic_year, term_no, start_date)
teaching_class(class_no, course_no, academic_year, term_no, capacity, active_count)
weekly_time(time_id, weekday_no, start_period, end_period)
teaching_assignment(class_no, teacher_no)
enrollment(enrollment_id, student_no, class_no, selected_at, withdrawn_at)
grade(enrollment_id, score, first_recorded_at)
grade_revision(revision_id, enrollment_id, editor_no, old_score, new_score, changed_at)
classroom(room_id, room_name)
class_schedule(class_no, time_id, room_id)
class_number_counter(academic_year, term_no, last_serial)
```

## 3. 数据字典

PK 为主键，UK 为唯一候选键，FK 为外键。标号 ①、②、③ 表示同一联合约束内的分量。除标注“可空”外，字段均为 NOT NULL。对应主外键字段使用相同类型、长度和比较规则。业务标识使用区分大小写的比较方式。文本长度按字符计，哈希长度按字节计。学期开学日期按北京时间记录，业务时刻按 UTC 存入 `DATETIME(6)`，再按北京时间计算学期窗口和展示。班级容量为人数上限，教室无座位数字段。

### T01 账号 `account`

来源 E01 / R01–R02。主键 `(account_name)`。

| 字段 | 数据类型 | 键和可空性 | 取值范围或说明 |
|---|---|---|---|
| `account_name` | `VARCHAR(7)` | PK | `admin`、`s`＋6 位数字或 `t`＋6 位数字，区分大小写，不可改名 |
| `role_code` | `CHAR(1)` | — | `A` 管理员、`S` 学生、`T` 教师，须与账号格式匹配 |
| `password_hash` | `VARBINARY(32)` | — | 恰好 32 字节，由应用配置 256 位输出。数据库仅保存哈希 |

### T02 学生 `student`

来源 E02 / R01。主键 `(student_no)`。另有候选键 `(account_name)`。

| 字段 | 数据类型 | 键和可空性 | 取值范围或说明 |
|---|---|---|---|
| `student_no` | `VARCHAR(24)` | PK | 1–24 字符的非空标识，保留前导零 |
| `student_name` | `VARCHAR(64)` | — | 1–64 字符，允许同名 |
| `account_name` | `VARCHAR(7)` | UK，FK → account.account_name | 学生账号，每个账号最多绑定一名学生 |

### T03 教师 `teacher`

来源 E03 / R02。主键 `(teacher_no)`。另有候选键 `(account_name)`。

| 字段 | 数据类型 | 键和可空性 | 取值范围或说明 |
|---|---|---|---|
| `teacher_no` | `VARCHAR(24)` | PK | 1–24 字符的非空标识，保留前导零 |
| `teacher_name` | `VARCHAR(64)` | — | 1–64 字符，允许同名 |
| `account_name` | `VARCHAR(7)` | UK，FK → account.account_name | 教师账号，每个账号最多绑定一名教师 |

### T04 课程 `course`

来源 E04 / R03。主键 `(course_no)`。

| 字段 | 数据类型 | 键和可空性 | 取值范围或说明 |
|---|---|---|---|
| `course_no` | `VARCHAR(24)` | PK | 1–24 字符的非空标识，保留前导零 |
| `course_name` | `VARCHAR(100)` | — | 1–100 字符，允许同名 |

### T05 学期 `academic_term`

来源 E05 / R04。主键 `(academic_year, term_no)`。

| 字段 | 数据类型 | 键和可空性 | 取值范围或说明 |
|---|---|---|---|
| `academic_year` | `CHAR(9)` | PK ① | `YYYY-YYYY`，后一年度比前一年度大 1 |
| `term_no` | `TINYINT UNSIGNED` | PK ② | 1 秋季、2 春季、3 小学期 |
| `start_date` | `DATE` | — | 北京时间周日。小学期等于同学年春季开学日加 126 天，创建后固定 |

### T06 教学班 `teaching_class`

来源 E06 / R03–R04。主键 `(class_no)`。

| 字段 | 数据类型 | 键和可空性 | 取值范围或说明 |
|---|---|---|---|
| `class_no` | `VARCHAR(22)` | PK | `学年-学期序号-流水`，流水不足三位补零，其余唯一十进制表示。编号创建后固定 |
| `course_no` | `VARCHAR(24)` | FK → course.course_no | 唯一所属课程，选课历史产生后冻结 |
| `academic_year` | `CHAR(9)` | 联合 FK ① → academic_term | 与 term_no 配对，匹配班号前缀 |
| `term_no` | `TINYINT UNSIGNED` | 联合 FK ② → academic_term | 1、2、3。建班后不迁移学期 |
| `capacity` | `INT UNSIGNED` | — | 1–4,294,967,295，创建后固定 |
| `active_count` | `INT UNSIGNED` | — | 0–capacity，默认 0，只随有效选退课在同一事务内增减 |

### T07 上课时间 `weekly_time`

来源 E07 / R13。主键 `(time_id)`。另有候选键 `(weekday_no, start_period, end_period)`。

| 字段 | 数据类型 | 键和可空性 | 取值范围或说明 |
|---|---|---|---|
| `time_id` | `BIGINT UNSIGNED` | PK | 正整数，系统生成 |
| `weekday_no` | `TINYINT UNSIGNED` | 联合 UK ① | 1–7，对应周一至周日 |
| `start_period` | `TINYINT UNSIGNED` | 联合 UK ② | 1–13，含起始节次 |
| `end_period` | `TINYINT UNSIGNED` | 联合 UK ③ | 1–13，且不小于 start_period，含结束节次 |

### T08 任课安排 `teaching_assignment`

来源 E08 / R06–R07。主键 `(class_no, teacher_no)`。

| 字段 | 数据类型 | 键和可空性 | 取值范围或说明 |
|---|---|---|---|
| `class_no` | `VARCHAR(22)` | PK ①，FK → teaching_class.class_no | 一班至少一名教师 |
| `teacher_no` | `VARCHAR(24)` | PK ②，FK → teacher.teacher_no | 同一教师可任教多个班，建班后任课集合固定 |

### T09 选退课记录 `enrollment`

来源 E09 / R08–R09。主键 `(enrollment_id)`。

| 字段 | 数据类型 | 键和可空性 | 取值范围或说明 |
|---|---|---|---|
| `enrollment_id` | `BIGINT UNSIGNED` | PK | 正整数，系统生成，每次重新选课分配新编号 |
| `student_no` | `VARCHAR(24)` | FK → student.student_no | 选课学生 |
| `class_no` | `VARCHAR(22)` | FK → teaching_class.class_no | 所选教学班 |
| `selected_at` | `DATETIME(6)` | — | 选课业务时刻，按 UTC 写入 |
| `withdrawn_at` | `DATETIME(6)` | 可空 | NULL 表示有效，非空表示已退，且不早于 selected_at |

### T10 当前成绩 `grade`

来源 E10 / R10。主键 `(enrollment_id)`。

| 字段 | 数据类型 | 键和可空性 | 取值范围或说明 |
|---|---|---|---|
| `enrollment_id` | `BIGINT UNSIGNED` | PK，FK → enrollment.enrollment_id | 一次有效选课至多一份成绩。无成绩行表示尚未录入 |
| `score` | `TINYINT UNSIGNED` | — | 整数 0–100。缺考录入 0 |
| `first_recorded_at` | `DATETIME(6)` | — | 按 UTC 写入。不早于选课时刻，首次录入后固定 |

### T11 成绩修改历史 `grade_revision`

来源 E11 / R11–R12。主键 `(revision_id)`。

| 字段 | 数据类型 | 键和可空性 | 取值范围或说明 |
|---|---|---|---|
| `revision_id` | `BIGINT UNSIGNED` | PK | 正整数，系统生成。用作记录标识与同一时刻的稳定排序补充 |

| `editor_no` | `VARCHAR(24)` | FK → teacher.teacher_no | 实际修改人，须属于该成绩所在教学班的任课教师 |

| `changed_at` | `DATETIME(6)` | — | 按 UTC 写入，距首次录入不超过 168 小时且不早于首次录入 |

| 字段 | 数据类型 | 键和可空性 | 取值范围或说明 |

| 字段 | 数据类型 | 键和可空性 | 取值范围或说明 |

## 4. 派生字段和数据约束

| 项目 | 落实方式 |
|---|---|
| 学期边界 | 秋季和春季各 18 周，小学期 4 周。结束日 = 开学日 + 教学周数 × 7 − 1。小学期创建时查同学年春季记录，取开学日加 126 天。小学期开学日仍作为学期事实列，等值规则在创建事务内检查 |
| 选退课窗口 | 秋、春常规窗口含开学时刻，至第 22 天 00:00 截止。期中退课为第 10 周周日至周三，以周四 00:00 为不含的结束边界。小学期仅开放开学起 3 天。有效选课、期中名额按任务一规定口径检查 |
| 教室命名 | 完整名称按“区号区楼号教楼层号房间尾号”生成。1、2、4 区各 5 栋，3 区 3 栋。楼层 1–5，房间尾号 01–27，共 2430 间。任务四可据此初始化 |
| 节次及冲突 | 13 个节次与钟点使用任务二第 2.2 节的固定表，关系中只存节次。两个闭区间重叠当且仅当起始节次分别不大于另一段的结束节次。在同学期、同星期检查教室、任课教师和学生的时间冲突。同一教学班自身的各个时段也不得重叠，即使使用不同教室；例如周一第 1–2 节与第 2–3 节冲突。调整排课只修改该班的排课引用，不修改其他班共用的上课时间定义。教学班一旦有过选课记录，即使后来退课，也不得修改该班所属课程、排课时间和教室 |
| 分数与统计 | 绩点由分数按 BR-09 换算，剩余人数由 capacity − active_count 计算，选课状态由 withdrawn_at 判定，退课类型由该班学期窗口与 withdrawn_at 唯一确定，统一在查询层映射为常规或期中。周总课时、平均分、逐分换算后平均绩点、及格和满绩以及选退课分项统计根据原始记录查询 |
| 有效人数 | active_count 为任务一规定的受控缓存，等于该班退课时间为空的选课数，校验 [0, capacity]，新增和退课事务同步维护 |
| 有效选课唯一性 | 对同一学生，按班取得课程和学期后检查“同课同学期仅一条有效选课”。历史行全保留。单用户顺序操作下在新增事务中查询并验证。单独对 `(student_no, class_no)` 设唯一键会阻断重选 |
| 班号永久唯一 | 由同学期 last_serial 加 1 得到流水，再按固定规则拼班号。发号和创建班在同一事务内完成，提交后才对外公布。删班保留该学期计数，计数到上限时拒绝发号 |
| 教学班删除 | 管理员删班时，同一事务内依次清除成绩修改、成绩、选退课、排课、任课和班级。课程、学期、教室、共享时间和发号计数保留。其他受引用对象依照 BR-13 限制删除 |
| 不能只用行约束的规则 | 账号绑定互斥及角色匹配、建班至少一名教师与一条排课、选课与改分权限、同课同学期各班周课时一致、跨行冲突、课期边界、成绩与退课互斥及有历史后的冻结由业务事务或数据库过程校验 |

同一课程在不同学期可以分别开班。一个班只在其所属学期排课，课程统计以课程号和学期联合范围汇总。删班后期中名额按现存记录重新计算，沿用任务一 BR-07。
