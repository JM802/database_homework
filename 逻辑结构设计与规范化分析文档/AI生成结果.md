# 高校教学管理系统数据库逻辑结构设计与规范化分析

> 本文保留本轮 AI 初稿候选模式。现行设计见[关系模式清单](关系模式清单.md)、[函数依赖分析](函数依赖分析.md)、[范式分析](范式分析.md)和[关系分解](关系分解.md)。

## 1. 背景与范围

依据任务一的选课规则和任务二的 E-R 模型，将关系、实体、键及属性域转换为关系结构，逐表检查 1NF、2NF、3NF，并解释分解正确性。

## 2. 关系模式初稿

| 数据对象 | AI 初稿候选模式 | 初稿考虑 |
|---|---|---|
| 账号和人员 | 账号、学生、教师各建表，在两类人员表上设唯一账号引用 | 两类身份共用账号关系 |
| 课程、学期、教学班 | 各建表，班引用课程与学期。学期候选列包含教学周数和结束日期 | 班级与课程、学期分别管理 |
| 上课时间、教室、排课 | 时间和教室单独建表。排课候选键有「班号、时间编号」和「班号、时间编号、教室编号」两种写法 | 一班可有多个时段，教室指定到单条排课 |
| 任课 | 以班号、教师工号联合标识 | 一班可有多位教师 |
| 选退课 | 选课记录号为主键，候选规则另对学生和班号施加唯一约束。保存状态、退课时刻和退课类型 | 希望减少重复选课并保留事件 |
| 成绩和改分 | 成绩依托选课记录，历史独立编号。成绩候选属性含分数、绩点、初录时间 | 支持查询当前成绩和改分轨迹 |
| 班号发放 | 初稿考虑使用该学期现存最大流水递增 | 简化发号状态维护 |

## 3. 函数依赖与初步判断

初稿识别班号决定课程、学期与容量，时间编号决定星期和节次，教室编号决定教室名称。将这些事实拼进排课宽表后，班号和时间编号分别可决定多列，属于部分依赖。课程名称间接依赖班号，教室名称属于教室资料。

选课记录号决定一次选课，成绩记录号沿用选课记录号，修改编号决定本次修改的快照。将当前分数和首录时间复制到每条修改记录会造成传递依赖。已有一次成绩可有多次改分。

## 4. 初步分解建议与验证

分别按课程号、学期键、时间编号、教室编号、班号投影排课宽表，保留班号和时间编号确定教室的排课关系。成绩、改分历史和选课按选课记录号分离。每步检查公共属性能否确定一侧，并核对原有依赖能否由子关系投影推出。

初稿留下四处需修正：同一班同一时段只用一个教室时，三字段排课键不是最小键。学生和班号不能限制全部历史唯一。现存最大流水不能保证删除后不重发旧号。学期结束时间、选课状态、退课类型和绩点均应明确保存或派生策略。修正及依据见[人工修改记录](人工修改记录.md)。
