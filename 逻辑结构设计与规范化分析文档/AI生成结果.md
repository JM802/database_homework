# 高校教学管理系统数据库逻辑结构设计与规范化分析（AI 初稿）

> 根据 Git 提交 `7129bef` 中留存的任务三 AI 初稿整理。后续改动见[人工修改记录](人工修改记录.md)。

## 1. 关系模式初稿

| 数据对象 | 初稿方案 |
|---|---|
| 账号、学生、教师 | 三者分别建表，学生和教师各自通过带唯一约束的账号字段引用账号表。 |
| 课程、学期、教学班 | 三者分别建表，教学班引用课程和学期。学期考虑保存教学周数和结束日期。 |
| 上课时间、教室、排课 | 上课时间和教室各自建表，每条排课指定一个时间和一间教室。初稿列了两种键的写法，分别是（班号，时间编号）和（班号，时间编号，教室编号）。 |
| 任课安排 | 以（班号，教师工号）标识一条任课记录，支持一个班由多位教师任课。 |
| 选退课记录 | 以选课记录号为主键，另考虑对（学生，班号）加唯一约束。记录选课状态、退课时刻和退课类型。 |
| 成绩和成绩修改历史 | 成绩沿用选课记录号，记录分数、绩点和首次录入时间。每条成绩修改历史单独编号。 |
| 班号发放 | 查出本学期现存班号的最大流水号，再加 1 生成新班号。 |

## 2. 函数依赖与范式判断

班号决定课程、学期和容量，时间编号决定星期和节次，教室编号决定教室名称。将这些字段放进同一张排课宽表时，班号和时间编号分别决定一部分字段。以（班号，时间编号）为键时，这些部分依赖使宽表不满足 2NF。课程名称经课程号间接依赖班号。

选课记录号决定一条选课记录，成绩也用这个编号标识。一条成绩可以有多次修改，每次修改的内容由修改编号决定。若把当前分数和首次录入时间也存进每条修改记录，就会产生传递依赖。

## 3. 初步分解方案

1. 按课程号、学期键、时间编号、教室编号和班号拆出课程、学期、上课时间、教室和教学班。排课关系保留班号、时间编号和教室编号，班号和时间编号共同确定教室。
2. 分开保存选课、当前成绩和成绩修改历史，通过选课记录号关联。
3. 每一步用公共属性能否决定其中一个子关系来检查无损连接，再检查子关系的函数依赖能否推出原来的依赖。
