# 函数依赖分析

关系结构与字段类型见[关系模式清单](关系模式清单.md)。只以项目明确的业务规则及已列出的唯一约束推导函数依赖。函数依赖 X → Y 指任意两条合法记录只要 X 相同，其 Y 就相同。主键、候选键或课表约束应依据业务允许的全体数据判定，不能从当前几条样例的碰巧唯一推断。

## 1. 记号和推导方法

A 账号名，S 学号，P 工号，C 课程号，Y 学年，N 学期序号，B 班号，T 时间编号，W 星期，F 开始节次，L 结束节次，E 选课记录号，H 修改记录号，R 教室编号。箭头右侧多列是同一左部推导出的各个属性的简写。

从 X 出发，反复加入能由现有属性推出的新属性，直到闭包不再变化。闭包含全表且 X 的任一属性不能去掉时，X 是候选键。下表列出各表非平凡依赖的生成依据。对右侧拆成单字段、排除平凡依赖即可用于闭包计算。对于双候选键表，可用键间双向决定加一侧到非键字段生成其余依赖。

| 关系 | 依赖生成依据 | 闭包与最小性推导 |
|---|---|---|
| 账号 | A → role, hash | A⁺ = 全表。除 A 外，角色可重复，哈希也无唯一业务约束。 |
| 学生 | S → A, name；A → S | S⁺ 与 A⁺ 均为全表。姓名不唯一，两个单属性候选键均无可部分依赖的真子集。 |
| 教师 | P → A, name；A → P | P⁺ 与 A⁺ 均为全表。姓名不唯一，账号与工号是两个单属性候选键。 |
| 课程 | C → name | C⁺ = 全表。课程名可重复。 |
| 学期 | Y,N → start_date | (Y,N)⁺ = 全表。Y 或 N 的闭包只有自身。N 只决定学期名称和周数等派生值。小学期与春季的日期关系是跨行规则。 |
| 教学班 | B → C,Y,N,capacity,active_count | B⁺ = 全表；同学期同课可多个班，(C,Y,N) 不决定班号或班容量。班号决定其前缀，前缀仍映射到学期键。 |
| 上课时间 | T → W,F,L；W,F,L → T | T⁺、(W,F,L)⁺ 均为全表。任一自然键真子集不能指定独立时段，例如周一第 1–2 节与 1–3 节。两个键的每个属性都是主属性。 |
| 任课安排 | 无非平凡表内 FD | (B,P)⁺ = {B,P}，B⁺ = {B}，P⁺ = {P}。每个班可有多位教师，每位教师可任教多班。 |
| 选退课记录 | E → S,B,selected_at,withdrawn_at | E⁺ = 全表。(S,B) 可能随退课重选重复，时间戳并非标识。withdrawn_at 为空是 SQL 状态表达，其含义由查询派生，不设状态或退课类型列。 |
| 当前成绩 | E → score,first_recorded_at | E⁺ = 全表。相同分数与录入时刻可出现多次。绩点若存储会形成 score → 绩点，故按分数计算。 |
| 成绩修改历史 | H → E,P,old_score,new_score,changed_at | H⁺ = 全表。一次选课可多次修改，同一时刻也不作为唯一性的业务承诺。旧分数、新分数均由本次修改标识确定。 |
| 教室 | R → room_name；room_name → R | R⁺ 与 room_name⁺ 均为全表。只有完整名称全校唯一，单独 101 等房间号可以重复。 |
| 教学班排课 | B,T → R | (B,T)⁺ = 全表，B⁺ = {B}，T⁺ = {T}。同班不同时间可有不同教室，同一时段不同班可在不同教室上课。 |
| 班号发放计数 | Y,N → last_serial | (Y,N)⁺ = 全表，Y 或 N 无法确定本学期的流水上限。不同学期可有相同流水上限。 |

## 2. 三个候选键计算实例

1. **教学班排课。** 从 {B,T} 起算，应用 B,T → R，得到 {B,T,R}。仅有 {B} 或 {T} 时无法应用该依赖。选择联合主键以后，R 是必须存在的外键。一班同一时段可以整体换教室，不能插两行同时上两间教室。
2. **上课时间。** 设 L₀ = {W,F,L}。从 L₀ 经 L₀ → T 到全表，从 {T} 经 T → W,F,L 也到全表。只知道星期和起始节次时可以同时存在两个不同的结束节次，只知道星期和结束节次时也可有不同起始节次。缺星期时不同工作日可引用相同起止节次。
3. **历史选课。** 设 E₁、E₂ 分别是退课前后两次选择同一教学班的编号。E₁ 与 E₂ 可有相同 S、B，而选课时间、退课时间等不同。即便其中仅一条有效，(S,B) 仍不能决定全部历史记录。

## 3. 派生值、条件规则与跨表依赖

- 课程名随课程号决定，教室名随教室编号决定，教师名随工号决定。这些依赖在基础表中成立。把名称复制进排课将带来非键决定非键或部分依赖。
- 学期序号决定教学周数，开学日期和学期序号决定结束日期。若将结束日期与开学日期重复保存，联合键先决定开学日期，再由开学日期和学期序号得到结束日期。逻辑层直接计算结束日期和教学周数。小学期开学日期等于同学年春季开学日期加 126 天，由跨行校验保证。
- 退课时刻为空与“有效”一一对应。有退课时刻时，按教学班所属学期和该时刻判定退课类型。常规与期中窗口互斥。若复制退课类型，`(class_no, withdrawn_at)` 在已退子集上会决定类型，但不是该子集的候选键。查询统一派生状态和退课类型，可避免保存矛盾值。
- “同课同学期至多一条有效选课”是筛选有效行之后，经教学班关联课程与学期才能判断的业务约束。它不是全部历史记录的普通 FD。教室不重叠、角色互斥、允许改分的期限与容量，也不能由一般函数依赖完整表达。
- 有效选课人数属于跨关系聚合一致性，`active_count = COUNT(本班未退选课)`。在教学班关系内它由班号决定，事务同步维护的必要性来自跨表冗余。
