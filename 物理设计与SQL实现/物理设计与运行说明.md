# 高校教学管理系统物理设计与运行说明

任务四选用本机已安装的 MySQL 8.0.41。数据库为 `university_coursework`，存储引擎显式指定 InnoDB，字符集和排序规则设为 `utf8mb4 / utf8mb4_0900_as_cs`。测试在单独初始化的本地 MySQL 实例中执行，使用 Windows 共享内存连接。建表脚本创建专用数据库，若数据库同名会停止。初始化脚本面向新建空库。类型以[任务三关系模式清单](../逻辑结构设计与规范化分析文档/关系模式清单.md)为准。

## 1. 运行顺序

| 文件 | 用途 |
|---|---|
| [01_create.sql](../sql/01_create.sql) | 建库、14 张关系表、主外键、唯一性、非空、检查约束和索引 |
| [02_seed.sql](../sql/02_seed.sql) | 初始化虚构数据、按规则生成 2430 间教室，并在同一事务中计算有效人数缓存 |
| [03_queries.sql](../sql/03_queries.sql) | 8 条要求的业务查询 |
| [04_audit.sql](../sql/04_audit.sql) | 14 张表的精确行数和 18 项测试样本的全库一致性检查 |
| [verify_mysql.py](verify_mysql.py) | 调用 MySQL 实际执行 SQL、比对结果和运行 13 个非法写入用例，生成原始输出 |

可以用 MySQL Workbench 依次执行四份 SQL，连接字符集为 UTF-8。已有 MySQL CLI 登录路径时，也可以在本目录运行以下命令。把 `coursework` 换成已配置的登录路径，连接用户须有建库权限。

```powershell
python .\verify_mysql.py --initialize -- --login-path=coursework
```

复核已初始化的同一测试库时省略 `--initialize`。负向用例各用独立事务，异常后关闭连接回滚，结束时重新核对行数与审计结果。夹具哈希是 SQL 验证用的固定 32 字节数据。任务五若用此库测试登录，需要以实际配置的 PBKDF2 参数和外部盐推导密钥为测试账号初始化真实哈希。


### Windows 命令行中文显示

SQL 文件采用 UTF-8 编码，数据库与连接采用 `utf8mb4`。在 Windows PowerShell 中运行 `chcp 65001`，然后使用 `mysql --default-character-set=utf8mb4 -u root -p` 登录，才能让终端显示编码和 MySQL 客户端字符集相匹配。`SET NAMES utf8mb4` 只设置连接字符集，不会自动修改终端编码。已有数据是否正确可按 [截图说明](截图说明.md) 中的十六进制检查确认；不要为解决显示乱码直接重建数据库。

## 2. 完整性与删除策略

- 各表以任务三候选键落实主键与唯一约束。排课主键为班号、时间编号，教室编号非空引用教室。学生、教师的账号各为非空唯一外键，账号格式约束与外键共同保证角色匹配。人员档案与账号成对创建仍由写入事务保证。
- CHECK 负责账号及哈希格式、学年和学期编号、星期与节次边界、教室名称、班号及学期前缀、有效人数范围、选退课时间顺序和分数范围。
- 外键保留默认的限制删除方式。管理员删班时，由同一事务按依赖顺序删除改分历史、成绩、选课、排课、任课及班级。共享对象和班号计数均保留。MySQL 的外键行为依据[官方外键说明](https://dev.mysql.com/doc/refman/8.0/en/create-table-foreign-keys.html)。
- 跨表和跨行规则由任务五业务写入事务落实，审计脚本对样本逐项复核。重点包括同课有效唯一、选退课窗口、师生教室冲突、改分资格和期限、至少一位任课教师与一条排课、人数缓存与发号。应用按北京时间判断窗口，业务时刻按 UTC 存储。示例查询的学生、教师和学期参数是验收样本，应用须从登录身份和用户选择绑定查询参数。

## 3. 索引设计

| 索引 | 查询路径及用途 |
|---|---|
| `ix_teacher_name (teacher_name, teacher_no)` | Q06 先按姓名找到工号，姓名允许重复 |
| `ix_assignment_teacher_class (teacher_no, class_no)` | 支持教师反查任课班，班号开头的任课主键支持反向路径 |
| `ix_class_course_term (course_no, academic_year, term_no)` | 同课按学期取班，支撑同课检查与课程统计 |
| `ix_class_term_course (academic_year, term_no, course_no)` | 先筛学期再按课程定位班，支持 Q02 和 Q08 |
| `ix_schedule_room_time (room_id, time_id)` | 教室反查排课，之后连接时间并比较闭区间；时间编号外键也有以时间编号为首列的索引 |
| `ix_enrollment_student_active (student_no, withdrawn_at, class_no)` | 按学生查修读史、有效选课与同课限制 |
| `ix_enrollment_class_active (class_no, withdrawn_at)` | 按班查名单和退课状态，核对人数缓存 |
| `ix_revision_chain (enrollment_id, changed_at, revision_id)` | 从成绩号按改分时刻和编号读历史 |
| 教室名称唯一索引、上课时间自然键唯一索引 | 教室名称查找及前缀匹配、节次组合去重 |

Q02 的余量由容量减有效人数派生，排序可能使用额外排序步骤。小型样本是否选用某个索引由优化器决定。

## 4. 查询对照

| 查询 | 类型 | 所覆盖的业务或语法 |
|---|---|---|
| Q01、Q02 | 单表 | `WHERE`、`ORDER BY`，教室与班级余量条件 |
| Q03、Q04 | 多表 | `INNER JOIN` 排课，`LEFT JOIN` 保留未录成绩的个人选课 |
| Q05 | 分组 | `GROUP BY`、`HAVING` 筛选有多次选课事件的班 |
| Q06、Q07 | 嵌套 | `IN` 按合授教师筛班，`EXISTS`／`NOT EXISTS` 过滤未录成绩 |
| Q08 | 复杂统计 | 多表连接、公共表表达式、独立聚合与分数换算；先汇总选课和任课再连接 |

## 5. 实际运行结果

MySQL 8.0.41 已执行建表和初始化。14 张表每张至少 10 行，教室表为 2430 行。8 条指定类型查询通过数据断言。18 项样本审计均返回 0，13 条非法 SQL 均被 MySQL 拒绝。另在事务中试删有选课及改分历史的教学班，验证共享教室、共享时间及班号计数均保留，回滚后被删班级和数据恢复。
